# GCC 12.5.0 + Binutils 2.43.1 LoongArch64 Docker Toolchain Builder
> Dockerfile based on LoongNix 20, builds GCC 12.5.0 and Binutils 2.43.1 natively on LoongArch64, producing loongarch64-linux-gnu toolchain (LP64D ABI)

## Overview
This repository provides a reproducible Dockerfile to build the following components from source on native **LoongArch64**:

- GNU Binutils 2.43.1 (as / ld / objdump etc.)
- GCC 12.5.0 (C / C++ compiler, LP64D ABI)

✅ Features:

- Native `loongarch64-linux-gnu` toolchain (not a cross-compiler; build host is LoongArch64)
- Build Binutils separately first; GCC is configured and linked against this new Binutils set to avoid outdated system binutils
- Fix LP64D dynamic linker symlink issue for LoongArch
- Update upstream `config.sub` / `config.guess` for correct LoongArch detection
- Block deprecated `-mabi=lp64` and enforce standard LP64D
- Final toolchain paths inside container: `/opt/gcc-12.5.0` and `/opt/binutils`

> ⚠️ Important: This image **can only be built on LoongArch64 hardware** (3A5000 / 3A6000 etc.). Build directly on x86_64 is not supported.

## 📦 Prerequisites

1. LoongArch64 machine with LoongNix 20 / Debian LoongArch
2. Docker / containerd runtime
3. Download source tarballs and place them alongside Dockerfile:

```bash
# binutils
wget https://sourceware.org/pub/binutils/releases/binutils-2.43.1.tar.xz
# gcc
wget https://ftp.gnu.org/gnu/gcc/gcc-12.5.0/gcc-12.5.0.tar.xz
```

Directory layout:

```plaintext
.
├── Dockerfile
├── binutils-2.43.1.tar.xz
├── gcc-12.5.0.tar.xz
└── README.md
```

## 🐳 Pull prebuilt image from Docker Hub

You can pull the pre-built toolchain image directly from Docker Hub without building locally:

```bash
docker pull lipengin1975/loongarch64-gcc:12.5.0-binutils-2.43.1
```

## 🚀 Build Image

```bash
docker build -t loongarch64-gcc:12.5.0-binutils-2.43.1 .
```

> Compilation takes a long time, depends on CPU core count. Multi-core machine is recommended.

## ▶️ Run Container

```bash
docker run -it --rm loongarch64-gcc:12.5.0-binutils-2.43.1
```

## 📂 Toolchain Paths

- Binutils: `/opt/binutils`
- GCC 12.5.0: `/opt/gcc-12.5.0`
- Shared libraries registered to system linker via `/etc/ld.so.conf.d/gcc-12.5.0.conf`, `ldconfig` executed automatically
- PATH is preconfigured to prioritize this new toolchain

## 📋 Build Details (Mapping to Dockerfile)

1. Build standalone newer Binutils first; GCC configure and build use this `as` / `ld` instead of system default
2. Replace `config.sub` / `config.guess` to resolve LoongArch detection failures
3. Wrap `gcc-upstream` / `gxx-upstream` wrapper scripts to reject invalid `-mabi=lp64`
4. Create symlink for LP64D dynamic interpreter
5. Patch `collect-ld` manually to avoid hardcoded `/usr/bin/ld` inside GCC
6. GCC configure flags: `--enable-languages=c,c++ --disable-multilib --disable-bootstrap`
7. Build sequence: `all-gcc` → patch collect-ld → full make && install

## 📌 Use Cases

- LoongNix development requiring newer GCC than distribution packages
- LoongArch embedded C/C++, Qt, edge gateway and industrial IoT projects
- Consistent CI build environment for team
- Extract and copy the standalone toolchain to other LoongArch machines

## ❗ Known Limitations & Notes

1. **Build only on LoongArch64 host**. QEMU emulation on x86 is extremely slow and prone to failure.
2. Source tarballs are expected locally; no on-the-fly download inside Dockerfile for offline build support.
3. Only C and C++ enabled. Add Fortran / Ada etc. by modifying `--enable-languages`.
4. `--disable-bootstrap`: skip GCC bootstrap to save build time. Remove this flag for high-assurance production validation.
5. ABI fixed to LP64D, incompatible with LP64S.
6. **ELF files generated by this compiler hardcode dynamic interpreter to `/lib64/ld-linux-loongarch-lp64d.so.1`**.
If this file does not exist on your target runtime system, binaries will fail with interpreter not found. Run this symlink command once on target:

```bash
ln -s /lib64/ld.so.1 /lib64/ld-linux-loongarch-lp64d.so.1
```
